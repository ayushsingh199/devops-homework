----- Task 1: Verify storage persistence -----
$ POD_NAME=web-app-bc8dfb4db-9ddl9
$ kubectl exec -n production-webapp "$POD_NAME" -- sh -c 'echo "Student: Ayush Singh" > /data/student.txt'
$ kubectl exec -n production-webapp "$POD_NAME" -- cat /data/student.txt
Student: Ayush Singh
$ kubectl delete pod -n production-webapp "$POD_NAME"
pod "web-app-bc8dfb4db-9ddl9" deleted from production-webapp namespace
$ NEW_POD=$(kubectl get pods -n production-webapp -l app=web-app -o jsonpath="{.items[0].metadata.name}")
NEW_POD=web-app-bc8dfb4db-kplbw
$ kubectl exec -n production-webapp "$NEW_POD" -- cat /data/student.txt
Student: Ayush Singh
(deleted pod != same pod, but the ReadWriteOnce PVC is still the same volume -- data survived)

----- Task 3: HPA elastic scaling -----
Already demonstrated with real CPU load against the registry.k8s.io/hpa-example app in Task 3
(task3-hpa.txt) -- plain nginx here would hit the same "too little real CPU work per request"
problem explained there, so this mini-project reuses that same proof rather than repeating an
unreliable nginx load test. The HPA object IS live and watching real CPU metrics:

NAME                      READY   STATUS    RESTARTS   AGE   IP           NODE     NOMINATED NODE   READINESS GATES

(web-app-bc8dfb4db-kxlv4 is the pod that was actually created to replace the deleted one --
 the earlier "$NEW_POD" grabbed kplbw, the untouched sibling replica, by coincidence of ordering.
 Checking the real replacement pod specifically:)
$ kubectl exec -n production-webapp web-app-bc8dfb4db-kxlv4 -- cat /data/student.txt
Student: Ayush Singh
(confirmed on the actual freshly-scheduled pod, not a pre-existing sibling.
 Caveat worth noting: ReadWriteOnce restricts a volume to one NODE, not one POD -- with both
 replicas on this single-node cluster, they could mount the same volume concurrently regardless
 of pod deletion. On a multi-node cluster this same PVC could only ever be attached from one node
 at a time, making the "survives Pod rescheduling" property much more load-bearing.)
