$ git init -q
$ echo "v1" > app.txt && git add app.txt && git commit -m "initial commit"

----- Demonstrating: git commit -m  (WITHOUT -a) -----
$ echo "v2 - edited" > app.txt        # modify a TRACKED file
$ git status --short
 M app.txt
$ git commit -m "try without staging"
On branch main
Changes not staged for commit:
  (use "git add <file>..." to update what will be committed)
  (use "git restore <file>..." to discard changes in working directory)
	modified:   app.txt

no changes added to commit (use "git add" and/or "git commit -a")

----- Demonstrating: git commit -a -m  (WITH -a) -----
$ git commit -a -m "edited via commit -a -m"      # auto-stages tracked+modified files
[main 9db584f] edited via commit -a -m
 1 file changed, 1 insertion(+), 1 deletion(-)
$ git log --oneline
9db584f edited via commit -a -m
0cbf4eb initial commit

----- Key difference -----
# "git commit -m" only commits what is already in the STAGING AREA (git add).
# "git commit -a -m" automatically stages any TRACKED file that was modified
# or deleted (but NOT new/untracked files) before committing, in one step.

----- Proving -a does NOT pick up new (untracked) files -----
$ touch newfile.txt
$ git commit -a -m "should not include newfile.txt"
On branch main
Untracked files:
  (use "git add <file>..." to include in what will be committed)
	newfile.txt

nothing added to commit but untracked files present (use "git add" to track)
(nothing to commit — as expected, -a ignores untracked files)
$ git status --short
?? newfile.txt
